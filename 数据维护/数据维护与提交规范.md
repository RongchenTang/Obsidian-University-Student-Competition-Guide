# 竞赛资料库：数据维护与提交规范

> 适用于「竞赛查询与奖金计算器」和「竞赛日历网页PPT」。两个网页的数据只来自资料库 Markdown（`重庆移通学院_学科竞赛导航资料库_….md`）。任何更新都要先改资料库，再重新生成网页数据。

## 一、角色分工

| 角色 | 谁 | 做什么 |
|---|---|---|
| 提交人 | 课题组同学 | 发现可更新的信息，找到官方证据，按模板提交 |
| 审核人 | 指导老师（或老师指定的组长） | 核对证据，逐行填写「通过 / 退回 / 需补充」 |
| 维护人 | 老师，或把审核通过的文件交给 Claude | 把通过的行写进资料库，重新生成数据并发布 |

**建议分工**：按方向分组，每组 1—2 位同学负责一类赛事，每月 1 日固定检查一次官网通知。

|---|---|

| 设计与数媒 | A33 未来设计师、A09 大广赛、A49 中国好创意、A66 数媒大赛 |

## 二、提交流程

```
提交人找到证据 → 填《数据更新提交模板.xlsx》→ 发给审核人
      ↓
审核人逐行填写「审核结果」（通过 / 退回 / 需补充）
      ↓
维护人把「通过」的行写入资料库 Markdown，并在第九节 9.2 记一笔
      ↓
打开「竞赛网页/03-更新数据.html」重新生成数据 → 推送到 GitHub → 网页自动更新
```

**文件命名**：`数据更新_提交人姓名_YYYYMMDD.xlsx`

## 三、两种提交方式

### 方式一：Excel 模板（推荐）
使用同目录的 **`数据更新提交模板.xlsx`**：
- 每种修改一张工作表，一行写一条修改。
- 只填浅黄色格子；灰色斜体是示例行，提交前删除。
- 填写编号后，灰色表头的那一列会自动显示对应的赛事名称；显示「编号不存在」就说明编号写错了。
- 最右边的浅橙色「审核」列由审核人填写。

### 方式二：文字快速提交（微信 / QQ / Obsidian）
只有一两条修改时，可以直接复制下面的格式，在微信或 QQ 里发文字，一条修改一段。审核人确认后，由维护人整理入库。

**时间节点**

【提交人】张同学　【日期】2026-11-20
【月份】4　【竞赛】第十八届蓝桥杯　【编号】A25、A26

## 四、证据要求

| 修改类型 | 可以接受的证据 | 不接受 |
|---|---|---|
| 时间节点标「已核实」 | 当届竞赛官网通知、组委会文件、学校/学院正式通知 | 往年通知、聊天截图、公众号转述（无原文链接） |
| 赛区对应 B 类 | 组委会通知中写明该赛区是全国赛的选拔赛；或学校附件2名单 | 只凭比赛名称相似推断 |
| C/D 类批准 | 学校批准文件（必须有文件编号） | 学院口头通知 |
| 赛事信息纠错 | 学校新版名单、承办单位正式通知 | 个人判断 |
| 获奖案例 | 官方获奖公示、学校官网报道 | 无来源的转载 |

找不到当届官方来源时，状态只能填「备赛参考」或「待公布」，不能填「已核实」。

## 五、审核清单（审核人用）

逐行确认：
- [ ] 证据链接能打开，并且确实写了这条信息
- [ ] 年份和届次对得上，没有把往年日期当成当届日期
- [ ] 事项类型准确：报名开始 ≠ 报名截止 ≠ 作品截止 ≠ 比赛日
- [ ] 编号正确（自动列显示的赛事名称和提交内容一致）
- [ ] C/D 类有批准文件编号
- [ ] 只适用于部分赛道的信息，已经写明赛道/组别

审核结果：
- **通过**：可以入库。
- **退回**：信息不对或证据不成立，请在「审核意见」写明原因。
- **需补充**：方向对但缺证据或缺字段，请提交人补完后重新提交。

## 六、入库：审核通过后怎么更新网页

### 做法 A：交给 Claude
把审核好的 Excel 发给 Claude，并说明：

> 请按《数据更新提交模板》中「审核结果 = 通过」的行更新资料库，记录到 9.2 维护记录，重新生成网页数据并推送。

Claude 只处理「通过」的行，其他行不会入库。

### 做法 B：老师手动更新
1. 在 Obsidian 里打开资料库 Markdown，按下表把每一行写进对应表格。
2. 在第九节 **9.2 维护记录**里补一行：更新日期、编号、修改字段、更新前、更新后、官方来源、核验人。
3. 用浏览器打开 `竞赛网页/03-更新数据.html`，把 Markdown 拖进去，看检查结果没有红色错误后写入。
4. 推送到 GitHub（或把更新后的「竞赛网页」文件夹发给同学）。

### 模板各列 → 资料库表格对照

| 模板工作表 | 写入资料库的位置 | 列的对应关系 |
|---|---|---|
| 1-时间节点 | 10.4 结构化日历节点 | 月份→月份；竞赛名称→竞赛；关联编号→关联ID；日期→日期；事项类型（＋赛道/组别）→事项类型，例如「省赛（软件赛道）」；届次年份→届次年份；状态→状态；证据链接→来源。如果替换的是「待公布」行，删除原行 |
| 2-别名 | 10.1 查询别名表 | 在对应编号那一行末尾加上新别名，用「、」分隔；编号还没有行就新增一行 |
| 3-赛区对应B类 | 10.2 A类赛事对应的选拔赛 | A编号、选拔赛层级名称、对应B编号、对应依据、状态，逐列照抄 |
| 4-CD类批准 | 5.1 C、D类校内审批名单 | 赛事ID 按 C01、D01 这样往后编；其余列照抄；状态写「已批准」 |
| 5-赛事信息纠错 | 第四节（A类）或第五节（B类）主表 | 找到编号所在行，把「修改字段」那一列改成新值 |
| 6-获奖案例 | 10.7 课堂案例 | 逐列照抄 |
| 7-其他建议 | 不直接入库 | 由老师判断是否需要调整网页功能 |

## 七、常见问题

**问：新一届比赛公布了日期，旧的「待公布」那一行怎么办？**
答：提交时在备注写明「替换 10.4 中 ×× 行」。入库时删除「待公布」行，加上新的「已核实」行。往年已核实的节点可以保留，作为历史记录。

**问：只有部分赛道公布了日期怎么办？**
答：填写「赛道/组别」。入库时写进事项类型，例如「省赛（软件赛道）」，避免学生误以为所有赛道都是这个时间。

**问：学校发布了新的 A/B 名单怎么办？**
答：不要逐条提交，直接把学校新文件交给老师，由老师（或 Claude）整体替换第四、五节，并重新核对 10.2 对应关系。
